# 0.2.0 实施计划

本版本将 Cursor 从宿主全局 Agent 接管改为独立任务域，恢复官方聊天与模型的正常行为。接口依据为 `architecture.md` 与 `research/` 的固定版本研究。真实授权、付费对话和用户 Desktop profile 不在自动执行范围。

| ---------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 依赖与安装 | 生产只保留 SDK/zod；Host 精确 peer+dev；共享 resolver；仅插入插件的 patch；同步预编译产物                        | 完整构建、原地升级及 Host 解析器激活通过         |

## 执行与完成判据

1. 以官方公开接口核对 settings、sidebar、main、远程流与独立服务生命周期，不用占位成功结果替代未核实功能。
2. 保留官方 loop、providers、默认模型及预设；Cursor factory 只在独立域实例化使用。生产依赖不携带另一套 Host 作用域包。
3. 使用真实 Harness 服务和离线 SDK 替身验证创建不发送、模型配置、多轮、流式、工具只展示、取消和恢复，并验证宿主普通聊天未被接管。
4. 验证账号本机 stored、远端 me/models 与真实对话的状态区别；Key 不进入日志、会话与客户端。
5. 执行 `npm run check`、包内容和隔离目录干净安装检查；生成并保留 `dist/` 与 `lib/`，不添加安装生命周期构建。
6. 最终文档与版本、产物和验证证据对齐后统一提交。自动执行不修改真实 profile、不调用计费模型。

恢复只适用于具有有效 checkpoint 且满足安全校验的任务。SDK `1.0.40` 创建未发送的空任务不写入 checkpoint，重启后标记 `unavailable` 并提示新建；checkpoint 丢失、上次运行未结束、取消五秒未确认停止或持久化失败时拒绝继续，不以新建同 ID Agent 伪造恢复。

## 验收状态

`0.2.0` 的完整类型、格式、生产构建与 87 项离线测试已通过。真实菜单插槽挂载、宽窄屏离线截图、旧版原地升级及官方 Host 解析器完整激活验证也已通过，证据记录于 [verification.md](verification.md)。真实 Desktop、浏览器授权、账号目录、计费运行和 Windows 沙箱保留为未实测，不能从离线替身结果推断成功。
