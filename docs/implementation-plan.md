## 执行顺序

1. 以官方源码核对 Typert、客户端扩展、AgentFactory、模型目录和 bundle patch 的真实契约，记录不支持的能力。
2. 账号宿主、客户端、原生运行时、构建集成并行实现；接口变更通知其他任务，避免重复修改同一文件。
3. 使用真实 Harness 服务生命周期和离线 Cursor 替身联调；验证模型选择传入实际运行配置，验证专用模式不会同时启动默认 Agent loop。
4. 独立检查认证秘密、事件去重、多轮消息、取消和卸载边界；补跨模块回归测试。
5. 执行 `npm run check`、包内容检查与隔离目录干净安装；构建并保留 `dist/`，不添加安装生命周期构建脚本。
6. 更新 README 与验收记录，只按实际证据填写已实现/自动验证/真实未验证；各执行任务不修改用户 profile；提交与推送由调度者在验收后统一处理。

## 完成判据

- 自动验证通过必须对应命令、测试或可复现的产物检查；单纯编写计划不计完成。
- SDK 本地 stored 登录、远端 me 与 models 验证、真实对话是不同事实；界面连接成功须基于远端 me 与 models 验证，不从本地 stored 状态推断。
- 不读取 SDK 私有凭据结构；Key 不进入客户端、会话和日志。
- 模型页面和 Cursor 运行使用同一目录与标识；不得冒用 DeepSeek namespace 或伪造成功结果。
- 删除 bundle patch 能恢复基底配置；卸载关闭活动任务并释放注册资源。
- 真实 Desktop 加载、浏览器授权、账号模型和计费运行保留用户手动验收状态。

## 执行结果

上述五条任务的实现与跨模块离线回归已落地。真实 Context、AgentRegistry、SessionStore、SessionProjectionRegistry、LlmRuntime、TypertRegistry 和官方 JSONL 持久化后端参与测试；Cursor 云端运行由SDK替身替代。全量检查与干净安装的最终证据见 verification.md；固定Git安装在调度者统一提交后单独记录。
